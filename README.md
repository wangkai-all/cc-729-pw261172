# Datalog 数据加工仓

一个小型的、可解释的**有限关系规则**数据加工仓：网页导入节点和直接关系，
用 Datalog 子集规则派生**可达关系**、**继承标签**和**没有被屏蔽的结果**。
只开放结构化表单与明确的 Datalog 子集，**不开放任意脚本**。

纯 Python 标准库 + 原生 HTML/JS，无任何第三方依赖。

## 快速开始

```bash
python3 server.py            # 打开 http://127.0.0.1:8000
python3 demo.py              # 命令行演示三个操作样例
python3 -m unittest discover -s tests   # 37 个单元/性质测试
```

`server.py` 参数：`--port`、`--host`、`--state warehouse_state.json`（持久化文件，
默认启用；`--no-persist` 关闭）。持久化只存**输入与规则版本**，结果由求值重建。

## 功能对照

| 需求 | 实现 |
| --- | --- |
| 网页导入节点和直接关系 | 左栏：逐条添加/撤销、批量导入（`edge(a, b).` 每行一条） |
| 派生可达关系 / 继承标签 / 未屏蔽结果 | 样例③的规则：`reach`（递归）、`inherit`（沿可达继承）、`visible`（分层否定过滤） |
| 结构化表单或 Datalog 子集录入 | 规则区「文本录入 / 结构化表单」两个标签页，表单会生成同样的 Datalog 文本 |
| 不开放任意脚本 | 解析器只接受白名单文法（事实、规则、`not`、变量、常量），其它一律 `ParseError` |
| 正向递归集合语义、有环必终止 | 每层朴素不动点迭代；事实与推导依据都是**集合**，环上不会重复追加 |
| 分层否定 | Tarjan SCC + 拓扑分层；否定只能引用更低层已完成的关系 |
| 负向环拒绝并显示循环路径 | SCC 内发现否定边即拒绝，返回 `p → q → p` 这样的循环路径与涉及规则 |
| 变量必须有正向约束 | 安全性检查：头部与否定文字中的变量必须出现在某个正向文字中（range-restricted，取值域有限） |
| 删除不能只撤一条推导 | 删除用 DRed 的有根支持变体：只有**所有证明路径都失效**结果才消失（见下） |
| 展开支持关系 | 结果区每条事实可点「溯源」，懒展开证明树；循环支持会标注 `⟳`，不会无限展开 |
| 添加和撤销边 | 数据区逐条添加/撤销，即时增量维护并显示本次增减 |
| 比较增量与整版重算 | 顶栏按钮：整版重算当前草稿并与增量维护结果逐条对比 |
| 输入和规则一起发布 | 「发布版本」冻结输入+规则快照并求值；版本卡片可回看当时的结果与证明 |
| 失败保留上一版可查结果 | 规则无效/求值异常 → 记录失败版本，此前成功版本不受影响、仍可查询 |

## 规则语言（明确的 Datalog 子集）

```
reach(X, Y) :- edge(X, Y).            % 规则
reach(X, Y) :- reach(X, Z), edge(Z, Y).
visible(X, T) :- inherit(X, T), not blocked(X).   % 分层否定
edge(a, b).                           % 事实
```

- 变量：大写字母或 `_` 开头（`X`、`Y`）；单独的 `_` 是匿名变量。
- 常量：小写标识符（`a`、`vip`）、整数、引号字符串（`'x y'`）。
- 注释：`%` 到行尾。
- **不支持**：脚本、算术、比较、函数符号、析取——解析即拒绝。
- **安全性**：头部与否定文字里的每个变量都必须出现在某个正向（非否定）
  规则体文字中，否则拒绝（取值域必须有限）。
- **分层否定**：否定文字引用的谓词必须属于更低层；`p :- not q. q :- not p.`
  这样的负向环会被拒绝，并显示循环路径 `p → q → p`。

## 求值与增量维护（正确性依据）

**整版求值**：按分层拓扑序，每层做朴素不动点迭代。事实集与推导集都是集合，
单调增长到不动点即停——环上路径无限多也不会追加重复记录（集合语义）。

**溯源**：每条派生事实记录它的全部推导 `Derivation(规则, 正向前件, 否定前件)`。
推导是"事实×规则"的超边，有限；网页的"溯源"就是在这张超图上懒展开。

**插入**：单调，沿分层继续迭代到不动点即可。

**删除**（DRed 的有根支持变体，逐层处理）：

1. **受影响集**：溯源超图中传递依赖于被删事实的本层派生事实（局部性）。
2. **有根支持**：受影响集内，仍存在"有限证明树"的事实——即有一条推导，
   其全部正向前件要么未受影响、要么本身已有根支持。这是最小不动点，
   **循环互证没有 base case，不会被误判为成立**。
3. **被删除 = 受影响 − 有根支持**。只有所有证明路径都失效的事实才消失；
   还有独立证明的事实（样例②的 `reach(a,c)`）会保留。

依据：删除只会缩小输入，旧溯源已记录全部可能的推导；受影响集内
"有根支持 ⇔ 仍属于新输入下的最小不动点"，所以删除是**精确**的，
重推阶段对纯删除不会再产生新事实（插入阶段才需要继续迭代）。

**否定是非单调的**：若某层规则的否定谓词（如 `blocked`）在本轮发生变化，
则**整层重算**该层（其所有输入——更低层——此时已是最终值，重算有依据且完备），
统计信息里会显示"整层重算 N 层"。

**增量 vs 整版对比**：`POST /api/compare` 用当前输入+规则整版重算，
与增量维护状态逐条 diff。性质测试（`test_random_edits_match_full_recompute`）
在随机图、随机增删序列（含环、标签、屏蔽、5 层分层）下断言两者始终一致。

## 三个操作样例（网页左上角一键载入，`demo.py` 同步演示）

1. **循环图**：`a→b→c→a` 成环、`c→d` 引出。`reach` 收敛到 12 条（有限），
   撤销 `edge(c,a)` 断环后，恰好 6 条失去全部证明的派生事实消失，增量=整版。
2. **两条独立证明**：菱形 `a→b→c`、`a→d→c`。`reach(a,c)` 有两条证明；
   撤销 `edge(a,b)` 后仍成立（剩一条），再撤销 `edge(a,d)` 才消失。
3. **屏蔽规则变化**：`badge` 沿 `follows` 继承（`inherit`），`visible` 用
   `not blocked` 过滤。发布 v1 → 修改屏蔽规则（`vip` 也被 `muted`）→ 发布 v2，
   两版结果并排可查；再演示负向环规则被拒绝、失败版本不影响上一版。

## 代码结构

```
engine.py   解析器、安全检查、分层（SCC）、不动点求值、溯源、DRed 增量维护
app.py      应用状态：草稿（输入+规则+增量状态）、版本仓库、发布/失败保留
server.py   纯标准库 HTTP 服务（JSON API + 静态页面）
samples.py  三个内置样例与非法规则示例
static/     单页前端（数据 / 规则 / 结果与溯源 / 版本仓库）
demo.py     命令行演示三个样例
tests/      37 个测试：解析、安全、分层、终止性、溯源、DRed、随机性质、版本流
```

## HTTP API 摘要

```
GET  /api/state                       草稿全貌（数据/规则/结果/版本）
POST /api/facts/import  {"text"}      批量导入事实
POST /api/facts/add     {"pred","tuple"}
POST /api/facts/retract {"pred","tuple"}     撤销（增量删除）
POST /api/rules         {"text"}      录入规则（拒绝时返回错误与循环路径）
POST /api/rules/from-form {"rules"}   结构化表单 → Datalog 文本 → 同一套校验
POST /api/publish       {"note"}      输入+规则一起发布（失败保留上一版）
GET  /api/versions/<id>/results       查看某版结果（含失败原因）
GET  /api/provenance?pred&tuple       展开一条结果的支持关系
POST /api/compare                     增量维护结果 vs 整版重算
POST /api/sample/<cyclic|diamond|masking>
```
